# 01 需求分析

## 用户目标

员工输入制度或产品问题，系统基于可追溯的企业资料给出可靠答案；若资料不足、相互冲突或工具不可用，应明确说明而不是猜测。

## 输入与输出

输入包括问题、可选对话历史，以及带文档 ID、版本日期、主题和正文的知识库。输出包括答案、真实引用、冲突、资料缺口、追问、任务状态和逐步 Trace。

任务状态为：`answered`、`needs_clarification`、`out_of_scope`、`failed`、`incomplete`。

## 验收映射

| 验收点 | 实现与测试 |
|---|---|
| 明确答案 | 年假、字幕案例；回答前读取原文 |
| 文档冲突 | D01 30 天与 D02 15 天并列引用，请求确认 |
| 资料外问题 | 两轮无结果后返回资料缺口 |
| 改写相似问题 | 别名扩展和字符词组检索 |
| 上下文追问 | 将最近用户主题与省略问句组合 |
| 工具失败 | 可注入检索临时失败和读取失败 |

## 非功能要求

可运行 CLI；可替换文档；不含真实密钥；最大步数有限；模型异常不泄漏内部错误；Mock 与真实模型入口明确区分。
